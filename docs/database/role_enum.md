# Role Enum Documentation

This document describes the `role` column constraints and enum values used in the Nova database schema.

## Definition

In the generated Prisma schema (`schema.prisma`), the auth `User` model contains:

```prisma
model User {
  id        String @id @default(uuid())
  email     String @unique
  role      Role   @default(MEMBER)
  // other fields …
}

enum Role {
  ADMIN
  MEMBER
  VIEWER
}
```

## Role Values

| Role | Description | Permissions |
|------|-------------|-------------|
| `ADMIN` | Organization administrator | Full access including user management, settings, all resources |
| `MEMBER` | Standard member | Can create, read, update, and delete their own resources |
| `VIEWER` | Read-only viewer | Can only read resources, no modifications |

## Default Role

New users are assigned `MEMBER` by default.

## Constraint Implementation

The `role` column is defined with a **CHECK** constraint at the database level to enforce that only the allowed enum values are stored. This is generated by the Prisma generator based on the AST enum definition.

## Zod Schema

The Zod generator produces a corresponding enum schema:

```typescript
export const RoleSchema = z.enum(['ADMIN', 'MEMBER', 'VIEWER']);
export type Role = z.infer<typeof RoleSchema>;
```

## Extending Roles

To add a new role:
1. Update the DSL enum declaration.
2. Run the generator — it will update the Prisma enum and the generated migration will include the new value.
3. Update the Zod schema accordingly.

> **Note**: Keep the enum values in sync across Prisma, Zod, TypeScript type definitions, and the middleware RBAC checks.
